Factory Inventory Management System

Architecture overview — full-stack demo with an in-memory (no database) data layer.

Vue 3 Vite FastAPI Pydantic JSON mock data

Tech Stack

Frontend

  • Vue 3 — Composition API
  • Vite dev server, port 3000
  • Vue Router (6 routes)
  • Axios HTTP client (api.js)
  • Custom SVG charts, CSS Grid layouts
  • Custom i18n (English / Japanese)

Backend

  • Python FastAPI, port 8001
  • Single-file app: server/main.py
  • Pydantic models for request/response validation
  • Uvicorn ASGI server
  • Package/env managed by uv

Data

  • No database — JSON files in server/data/
  • Loaded into memory once at startup
  • Inventory, orders, demand, backlog, spending, transactions, purchase orders
  • Changes don't persist — restart reloads from disk

Tooling

  • pytest + FastAPI TestClient
  • Claude Code subagents (vue-expert, code-reviewer, security-auditor)
  • MCP: GitHub + Playwright
  • Custom slash commands: /start, /stop, /test

Request / Data Flow

1

User adjusts a filter or navigates

A view (e.g. Dashboard.vue) reads/writes shared filter state via the useFilters composable — Time Period, Warehouse, Category, Order Status.

2

View calls the API client

getCurrentFilters() builds a query-params object, passed into a method on client/src/api.js, which fires an Axios request to http://localhost:8001/api/....

3

FastAPI route filters in-memory data

server/main.py applies shared helpers (apply_filters, filter_by_month) against the Python lists exposed by mock_data.py — no database query, just list comprehensions.

4

Pydantic validates the response

Each route's response_model (e.g. InventoryItem, Order) shapes and validates the outgoing JSON before it's sent back to the browser.

5

Vue stores raw data, derives the rest

Responses land in refs (e.g. allOrders, inventoryItems); computed properties derive totals, chart series, and filtered subsets — cached until a dependency changes.

Notable Design Decisions

No database, no auth

All data lives in JSON files loaded once at startup. useAuth is a mocked, always-authenticated user — there's no real login flow.

Composables are singletons

useFilters, useAuth, and useI18n hold their reactive state at module scope, so every component sharing an import shares one instance of that state.

Backend is one file

All models and routes live together in server/main.py — there's no models.py/services/ split yet.

Inventory has no time dimension

Only warehouse and category filters apply to inventory; month filtering only makes sense for orders, which carry an order_date.

api.js is ahead of the backend

A few client methods (getTasks, createPurchaseOrder, etc.) call endpoints that don't exist yet in main.py — a sign of frontend-first iteration on this demo.

Backlog is modal-based, not routed

Backlog.vue exists but has no entry in the router — backlog detail is surfaced via BacklogDetailModal.vue instead of its own page.
